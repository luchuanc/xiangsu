# 移动端 UI 与交互规格

## 文档状态

- 版本：UI-1.2
- 状态：CONFIRMED（随 REQ-1.2 冻结）
- 规范性：移动触控、信息层级、构筑反馈与关键演出为首版验收输入

## 1. 坐标与安全区

- 设计坐标：`640 × 360`。
- Pixi 根布局按 `scale = min(viewportWidth / 640, viewportHeight / 360)` 缩放并居中。
- 568×320 等非整数比例视口允许 CSS contain 的小数缩放；逻辑坐标/布局边界取整数，纹理始终 nearest。交互层把 CSS 门槛换算为逻辑值：`hitSizeLogical=ceil(48/scale)`、`gapLogical=ceil(8/scale)`、`longPressMoveLogical=ceil(8/scale)`，最终以浏览器测得的 CSS 命中矩形不小于 48×48、间隔不小于 8px 为准。
- DOM 读取 `env(safe-area-inset-*)`，换算为逻辑像素后生成 `safeRect`；所有 HUD 以 `safeRect` 锚定。
- 超宽屏只扩展背景或留暗色边，不把战斗双方拉到 640 设计区之外。
- 1024×768 等较窄横屏按 contain 显示，顶部/底部允许背景留白。

## 2. 全局层级

```text
DOM shell
├── canvas
├── orientation / unsupported-size overlay
├── fatal-load / save-error overlay
└── accessibility status region

Pixi stage
├── sceneRoot
├── hudRoot
├── screenRoot
├── modalScrimRoot
├── modalRoot
├── toastRoot
└── transitionRoot
```

- 一个时刻只存在一个主场景。
- `screenRoot` 最多一个全屏功能页。
- `modalRoot` 可堆叠，但深度最多 2；浏览器返回只关闭最上层。
- 模态层打开后，下层 `interactiveChildren = false`，避免点穿。

## 3. 通用触控规则

- 主要按钮 CSS 命中区不小于 48×48，视觉图标可小于命中区。
- 相邻主要按钮边缘至少相隔 8 CSS 像素。
- 按下态在 `pointerdown` 立即显示；`pointerupoutside`、`pointercancel` 恢复。
- 长按 450ms；位移超过 8 CSS 像素或第二指针夺取控件时取消。
- 长按位移在事件 CSS 坐标中直接判断；若进入 Pixi 逻辑坐标再判断，必须使用本节的 `ceil(8/scale)` 换算，不能把 8 个逻辑像素误当成 8 CSS 像素。
- 同一指针只能被一个控件拥有；摇杆记录自己的 `pointerId`，忽略其他 move/up。
- 禁止依赖 hover；长按和“i”按钮均能打开说明。
- 所有不可用按钮必须同时降低视觉强度、禁用交互并提供点击/长按原因说明。

## 4. 横竖屏与系统状态

### 4.1 竖屏提示

- 条件：`viewportHeight > viewportWidth`。
- 内容：旋转图标、`system.rotate_device`、当前存档状态。
- 行为：停止 ticker、清空指针、禁止 canvas 事件；不销毁场景。
- 横屏恢复：重新计算 viewport 和 safeRect，渲染一帧后才恢复输入。

### 4.2 不支持尺寸

- 条件：横屏但 CSS 宽或高低于 568×320。
- 内容：`system.viewport_too_small`。
- 行为与竖屏相同。

### 4.3 保存失败

- 顶部常驻红色条，不自动消失。
- 文案：`error.SAVE_FAILED`。
- 操作：`system.retry_save`、`system.view_reason`。
- 成功后显示 2 秒 `system.saved` 再移除。

```text
┌──────────────────────────────────────────────────────────────┐
│ 队伍生命简条                         地图  背包  队伍  设置 │
│                                                              │
│                         世界画面                             │
│                                                              │
```

- 左上显示四个小头像与生命条；点击打开角色页。
- 右上 4 个图标：地图、背包、队伍、设置；战斗触发锁定后全部禁用。
- 左下动态摇杆最大视觉半径 44 逻辑像素，起点限制在 safeRect 左侧 45% 区域。
- 右下交互按钮为 56 逻辑像素圆形命中区；根据最近对象切换对话、开启、进入、拾取图标。
- 无交互目标时按钮半透明且不可点。
- NPC 名称和交互提示只在半径 40 逻辑像素内显示。
- 宝箱点击后立即锁定交互并显示 `common.loading`；只有资产与 opened object 同一存档事务成功后才隐藏宝箱并显示 `exploration.chest_received`。容量/revision/保存失败时恢复原宝箱和按钮，不能先播已领取演出或进入可部分挑选的奖励页。

## 6. 对话与 NPC 页面

### 6.1 对话框

- 位于安全区底部，宽度 `safeRect.width - 24`，高度 104。
- 左侧头像 72×72；右侧显示名称、最多 3 行正文和继续指示。
- 文本较长时分页，不使用滚动长段落。
- 点击正文区域或继续按钮进入下一页；长按不跳过。

### 6.2 功能页通用状态

| 状态 | 必须表现 |
| --- | --- |
| loading | 保留页框架，中央像素加载图标，操作禁用 |
| empty | 插图、原因文案和唯一建议动作 |
| error | 错误摘要、重试、返回；不能只写控制台 |
| disabled | 控件可见、原因可查询 |
| success | 数据提交后更新列表，显示 2 秒轻提示 |

### 6.3 七类 NPC 功能页

| NPC | 主区域 | 主操作 | 关键状态 |
| --- | --- | --- | --- |
| 酒馆 | 左侧招募列表、右侧 2×2 阵型 | 查看条件、招募、进入编队预览 | 已招募项不可重复；金币不足/任务未完成显示精确原因 |
| 铁匠 | 背包列表、装备详情、分解/重铸标签 | 批量分解、锁定普通词条槽并从 1～3 条稳定候选中确认 | 已装备/锁定/深渊槽禁用；材料、固定槽、reforgeCount 和本次成本始终可见 |
| 技能导师 | 角色、技能列表、两个主动槽、铭石、调谐专注 | 升级、装配、重置、铭石重铸、设置下一远征专注角色 | 等级/点数/互斥冲突明确展示；专注角色必须已招募，活动远征中不可修改 |
| 商人 | 购买、出售、回购三标签 | 购买 offer、出售未锁定物、回购会话最近 10 件 | 已售 offer 保留“已售”；回购在返回标题/刷新后为空并说明会话规则 |
| 旅店 | 队伍生命概览 | 免费完整恢复 | 全员满生命时按钮禁用并显示 `town.no_rest_needed` |
| 地图学家 | 楼层列表、敌人图鉴两标签 | 查看已解锁层和已发现敌人 | 未发现条目只显示轮廓；不泄露未解锁层掉落 |
| 深渊守望者 | 深渊规则、第 6～10 层概览、回响次数与 10 张挑战卡 | 阅读说明、打开层数选择、开始深渊回响 | 第五层未首通时展示 `lockReasonKey`；第十层未首通时回响标签显示完成主线条件，不进入空白页 |

- 商店、招募、旅店和铁匠提交期间关闭返回与重复点击；只有持久化成功后刷新余额/列表。
- NPC 页面返回时恢复城镇原坐标和朝向，不重建远征或刷新商店。
- 重铸预览横向展示最多 3 张候选卡；刷新页面、关闭再打开时顺序与 roll 完全相同。点击候选只切换选中态，第二次 `reforge.confirm_candidate` 才扣料；取消明确显示 `reforge.lock_warning`。

## 7. 战斗界面

```text
┌──────────────────────────────────────────────────────────────┐
│ R2  行动顺序: [A][敌][B][敌][C]          ×1  辅助  暂停   │
│ Boss 70%│35%   意图: 终焉湮灭·群体暗 [防御]  狂暴: 3     │
│                                                              │
│ [我方前] [我方后]                    [敌后] [敌前]           │
│ [我方前] [我方后]                    [敌后] [敌前]           │
│                                                              │
│ 当前角色头像/HP      普攻   技能   防御   道具   更多       │
└──────────────────────────────────────────────────────────────┘
```

- 顶部时间线最多显示 10 个头像，超出可横向分页但当前与下 5 个始终可见。
- 当前行动者脚下显示高亮环；行动者头像和名字同步高亮。
- 一级操作严格为普攻/技能/防御/道具/更多五个 48px 按钮；技能打开不遮挡单位区的二级抽屉，依次显示主动槽 1、主动槽 2、终极，空主动槽保留 disabled 占位；更多只含撤退和战斗日志。568×320 不再把 7 个按钮横向硬挤。
- 技能按钮显示图标、冷却数字和能量；不可用时显示原因。打开任一抽屉不消耗行动，点击原按钮或遮罩关闭。
- “道具”只列库存大于 0、category=consumable 且 useContexts 包含 battle 的物品；目标规则读取物品定义。提交后必须等待同一存档事务成功才冻结数量并播放事件，保存失败保持当前行动者与选择态且不扣物品。
- 第一次点击技能进入 `targeting`，合法目标发光，不合法目标降暗；第二次点击合法目标提交。
- 点击已选技能或取消区域退出 targeting，不消耗行动。
- 全体/自身技能第一次点击后在按钮上方出现 1.5 秒确认条；再次点击确认，点击其他位置取消。
- 长按单位显示属性、状态和速度；长按技能显示等级、公式结果、词条来源与 Combo 影响。
- 动画播放时只保留暂停与倍速按钮可用，其余输入冻结。
- Boss 战撤退按钮显示锁图标并说明原因。
- Boss HUD 固定显示狂暴倒计时“狂暴：N 轮”；进入阈值前一轮变为橙色，狂暴成功后替换为不可驱散状态图标与“攻击 +50%”。控制导致 Boss 尚未实际施放时显示“已到阈值，待 Boss 行动”，不能提前假装已狂暴。
- Boss 生命条按 `bossPhaseThresholdBps` 画 1～2 条刻度，进入阈值前即显示，不从中文或技能名猜阶段。待释放意图卡固定展示技能名、单体/群体、元素、counterKind 图标与“下次合法行动”；受控后加“已延后”，狂暴抢占时加“狂暴优先，意图保留”。
- 辅助开关只在 R-024 合法场景显示。自动倒计时以按钮环形 350ms 进度表示；任意触摸立即取消本次倒计时但不强制关闭长期开关。Boss、未首通层和回响完全不渲染辅助开关，不能只做 disabled 灰态误导可用性。

### 7.1 `BattleDomainEventV1` 表现映射

BattleAnimator 必须对判别联合做穷尽 `switch`；时间取 ASSET-1.2，×2/reduced/跳过只改变表现时间与震动，不改变事件消费顺序：

| event type | 唯一最小表现 |
| --- | --- |
| `PHASE_CHANGED` | 不单独播放；刷新阶段/时间线投影 |
| `ACTION_STARTED` | visualSkillId 非空时播放对应动作；defend 显示 300ms 防御图标，item 等待后续效果，retreat 不播放攻击动作，skip 不停顿并等待紧随的 TURN_SKIPPED 提示 |
| `INTENT_DECLARED` | Boss 上方 350ms 元素几何标识聚合到意图卡，不播放技能命中特效；卡片落位后刷新 HUD |
| `INTENT_RELEASED` | 清除/转入“释放中”，真实 ACTION_STARTED 和后续效果按技能动画播放 |
| `INTENT_CLEARED` | 无攻击表现，移除意图卡；原因只进详情日志 |
| `DAMAGE_RESOLVED` | 在 impact 时刻播放目标 hit、元素命中特效及 shieldDamage/hpDamage 数字；0 值不造假数字，critical 加 `battle.event.critical` 角标 |
| `HEAL_RESOLVED` | 绿色 healed 数字；overheal>0 追加 `battle.event.overheal` 小标，不能显示为实际回血 |
| `SHIELD_GRANTED` | 护盾特效与 granted 数字；discardedByCap 只进详情日志 |
| `STATUS_CHANGED` | applied/refreshed/stacked 更新图标；是否播放 status preset 只由下方 visualSkillId/内联分类规则决定，不能额外重复一次；resisted/immune 分别显示对应 `battle.event.*` 短字，capped 只进详情日志；consumed/dispelled/expired/depleted 只移除或更新图标 |
| `RESOURCE_CHANGED` | HP 区旁的能量/技能冷却数字补间；跳过时直接显示 after |
| `UNIT_SUMMONED` | 对应槽位 summon preset 后显示单位；无空槽不会产生该事件 |
| `UNIT_DEFEATED` / `UNIT_REVIVED` | down clip / heal preset 后恢复；时间线同步移除或等待下一轮加入 |
| `TURN_SKIPPED` | control 显示状态名和 `battle.event.turn_skipped`，defeated 仅跳过时间线，不弹文案 |
| `EXTRA_TURN_RESOLVED` | granted 显示 `battle.event.extra_turn`；suppressed 只进战斗详情日志 |
| `COMBO_TRIGGERED` | 按 10.1 的本场首触发/同根折叠规则显示，不在此事件中计算伤害 |
| `TRIGGER_REJECTED` | 玩家界面不显示；开发日志保存 reason/consumedRng |
| `ACTION_FINISHED` | 将该根行动最终状态投影为当前 HUD，不额外停顿 |
| `BATTLE_FINISHED` | 锁定指令并播放胜负最小演出 |
| `ABYSS_ECHO_EVALUATED` | success 显示目标达成；失败按固定顺序列轮数/倒地/Combo 未达标，随后返回城镇，不伪装成普通战败 |
| `REWARD_PREPARED` | 校验 transactionId 与 snapshot.reward 一致后进入战利品页 |

effect 的前摇选择规则固定为：`visualSkillId!=null` 播放该技能 AnimationDefinition；否则仅当 `effect!=null` 且（`triggerSource!=null` 或 rootActionDefinitionId 在 Item Catalog 中存在）时走 ASSET-1.2 内联分类器。根技能 effect 事件不得再次播前摇，DEFEND 只使用 ACTION_STARTED 的防御提示。点击跳过会立即消费尚未播放的事件并投影 `BattleResolutionV1.snapshot`，不得逐条重新调用领域服务。

## 8. 背包与装备

### 8.1 布局

- 全屏页，上方标签：装备、技能铭石、消耗品、材料。
- 溢出仓非空时在最前显示红色“溢出仓 N/30”标签；只能移动到有空间的对应背包或直接分解，不能从溢出仓直接装备。
- 左/中部为 5 列格子；右侧或底部详情随屏幕宽度切换，但仍在 640×360 设计区内。
- 底栏提供筛选、排序、批量分解、关闭。

### 8.2 操作

1. 单击格子选中。
2. 详情显示基础属性、每条词条、随机区间位置、锻造特性、适用角色和 Combo 标签；标签只按 LOC-1.2 的 `tag.<ComboTagId>` 显示中文，不展示或拆分内部 tagId。
3. 点击“装备”进入角色/槽位选择。
4. 显示换装前后属性差、技能效果差、Combo 新增/失去；关键输出/生存变化统一显示绝对值和百分比，百分比分母为换装前最终预览值，分母为 0 时显示 `upgrade.newly_gained` 而非无穷大。
5. 点击“确认”一次性提交；失败时保持预览不变。
6. 消耗品页仅在当前物品的 useContexts 包含当前场景时显示“使用”：野外从当前四人队伍选择存活未满血目标后提交 UseFieldItemCommandV1；满血、倒地、非队员、库存为 0 或战斗锁定时禁用并显示明确原因。战斗内物品只经战斗指令面板选择，不从全屏背包旁路扣除。

- 不以拖拽作为必要路径。
- 锁定按钮即时保存。
- 批量模式下已装备、已锁定和高于筛选上限的物品不可勾选。
- 技能铭石详情额外显示每条技能词条的 `stackRule`、目标范围和冲突说明：skill 目标显示本地化技能名，family 目标读取 `skill_family.<SkillFamilyId>`，allSkills 读取固定键；`exclusiveGroup` 只比较不展示，冲突项显示双方本地化词条名。
- 离开城镇前若溢出仓非空，层数选择确认按钮禁用并提供“前往清理”入口。
- 野外药水提交期间锁定“使用”与返回；只有持久化成功后更新数量/生命条。保存失败保留物品选中态和目标选择，可安全重试且不播放回血反馈。
- 当预览命中“关键掉落”门槛时显示分级徽记：中性目标 +15%～30% 使用 `upgrade.breakthrough`，中性常驻 >30% 使用 `upgrade.outlier`；元素 morph 从当前 Boss 抗性切到弱点时使用 `upgrade.counter_jump`，不冒充全局提升。分母为 0 时使用 `upgrade.newly_gained`。激活 Combo 时另列其触发窗口提升，不与常驻属性相加伪造一个总百分比。

## 9. 角色、队伍与技能

### 9.1 队伍页

- 左侧角色列表，右侧 2×2 阵型。
- 点击角色再点击槽位完成预览；主角移出时阻止并提示。
- 同一角色不能占两个槽位。
- 确认前展示队伍 Combo 变化；取消不修改真源状态。

### 9.2 技能页

- 顶部选择角色。
- 左侧显示 4 个主动技能及等级；中部两个装备槽；右侧技能详情与铭石影响。
- 技能点为 0 时升级按钮禁用。
- 等级未到的技能显示解锁等级。
- 重置按钮二次确认，说明会返还的点数。

### 9.3 Combo 页

- 标签：`combo.active`、`combo.reachable`、`combo.codex`。
- 已激活项展示来源树：角色 → 技能/装备/铭石 → 标签。
- 可达成项显示缺少的标签数量，不直接推荐某一具体掉落。
- 被预算限制或互斥阻止的效果在说明中明确展示。
- 提交装备/技能/编队后若首次满足 Combo，在同一成功存档事务把 ID 追加到 `discoveredComboIds`，随后显示 900ms 配方拼合卡（Combo 名、三类来源和核心效果）；保存失败不播放。再次卸下/装回不重复全屏演出，只显示普通新增提示。

### 9.4 层数选择与卡点诊断

- 每层卡片固定显示推荐 Boss 等级、推荐物品等级、gate 类型、Boss 弱点和狂暴回合。未解锁层只显示编号与锁定条件，不泄露掉落。
- 未首通层只显示“完整远征”；已首通层显示“完整远征 18～25 分钟”和“短程刷取 8～12 分钟”两个明确入口，不使用一个含糊的“进入”。短程详情固定列 3 普通、1 精英、1 宝箱、无 Boss/首通/回响次数。
- `bossRetryUnlockedFloorIds` 命中且 Boss 尚未首通时，卡片置顶“直接重试 Boss 2～5 分钟”；首通后整块入口移除。入口说明正常消耗生命/道具并可获得 Boss 与首通奖励，禁止误写成无消耗练习模式。
- 当前队伍全员 currentHp=0 时所有“进入”按钮禁用并显示 `error.INVALID_PARTY.ALL_DEFEATED`；编队页本身仍可保存该阵容，旅店恢复后无需重新编队。
- 队伍装备等级固定为 `floor(所有出战角色六槽 itemLevel 总和 / (出战人数×6))`，空槽按 0；同时逐角色显示等级与装备等级，不能只用队伍均值遮住短板。
- 第一次战败后记录只含本场统计的诊断卡：若 Boss 狂暴后才败，首要提示“输出未过门槛”；若狂暴前有角色倒地，提示“生存/净化未达标”；若弱点伤害占直接伤害低于 20%，提示“弱点利用不足”。多个条件按上述顺序显示，数据不足时不猜测具体装备。
- 诊断卡提供“重刷本层”“去铁匠”“去技能导师/Combo”三个明确入口；它是解释工具，不自动换装或修改构筑。

### 9.5 深渊回响页

- 顶栏显示 `回响次数 N/5` 和获取说明“完整通关第 6～10 层 Boss +1”；没有倒计时、日期、赛季或联网标识。
- 10 张卡按楼层 6→10、同层 1→2 排序，固定展示四项敌方倍率、狂暴提前轮数、道具上限、三项目标、深渊升格 bonus 和一次性材料。数值直接读 AbyssEchoDefinition，不拼 raw ID。
- storyCompleted=false 时挑战区只显示第十层首通条件；次数为 0 时开始按钮 disabled 并提供“前往完整深渊远征”。队伍全倒地或溢出仓非空沿用现有阻断入口。
- 点击开始先显示确认页，明确“消耗 1 次，战败不返还”；提交期间锁定返回/重复点击。保存失败次数不变并停在确认页，成功后直接 attach BattleScene。
- 已首通回响显示首通勾选并把材料行改为“已领取”；重复挑战仍显示增强 Boss 掉落。目标未达成结算页只提供“回城整备”，不能在未保存清理前连点再次扣次数。

## 10. 战利品页

- 奖励在战斗后集中出现；金币、经验、材料先列，装备和铭石使用横向卡片。
- `stackableCapConversions` 在金币下方逐项显示“<物品> 已达 9999：×N → G”；展开说明写明按基础价值 100% 转化，不与商店 25% 出售率混淆。
- 新 Combo 可能性用“可激活”提示，但不自动换装。
- 背包有空间时“全部领取”可用。
- 空间不足时突出溢出数量，并提供“前往分解”；奖励事务保持未提交。
- 领取按钮提交期间显示 loading 并防连点；成功后才允许返回地图。
- bossRetry 与 abyssEcho 奖励成功后按钮文案固定为“返回城镇”，不会尝试 attach 野外地图；回响目标失败没有战利品页。
- rare+ 当层武器、机制词条、深渊词条或会新增 Combo 的物品标记为关键掉落。卡片先停留 350/500/700ms（rare/epic/abyss），显示对应角色的关键值变化与 Combo 差异；点击可跳过等待但不能绕过领取事务。

### 10.1 爽点演出与信息预算

| 事件 | 标准表现 | reducedFlashes/reducedScreenShake |
| --- | --- | --- |
| 关键装备/铭石获得 | 品质光柱、卡片弹入、1 次 2px/80ms 轻震；深渊额外 600ms 暗紫边框流光 | 无白闪、无震动，保留边框动画和音效 |
| Combo 首次获得 | 900ms 配方节点依次点亮，最后显示核心效果；不自动装备 | 节点改为同时淡入，无强闪 |
| 每场首次触发某 Combo | 战场上方 700ms 横幅+来源图标，伤害数字使用 Combo 边框 | 400ms 静态横幅，不震屏 |
| Boss 破阶段 | 300ms 时间缩放只作用动画，不阻塞规则；阶段名和不可驱散图标 | 无时间缩放，保留阶段名 |
| Boss 击败/首通 | 800ms 定格、首通奖励预告、下一层解锁 | 400ms 定格，无闪烁 |

- 同一根行动最多显示 1 个大横幅；其余触发折叠到图标和战斗日志，避免 Combo 链遮挡操作。演出计时不进入领域状态、RNG 或存档结果。
- ×2 战斗速度缩短战斗内演出一半，但 Combo 首次获得和奖励卡不受倍速影响；所有演出可点击跳过到最终信息态。

## 11. 标题、暂停与设置

### 11.1 标题

- 有存档：继续游戏、新游戏、设置。
- 无存档：开始游戏、设置；继续游戏不显示。
- 新游戏覆盖已有存档时使用两步确认，第二步按钮文案为“覆盖并开始”。

### 11.2 暂停

- 返回游戏、回城、设置、返回标题。
- 野外回城会结束远征并二次确认；确认文案明确“不回血、本轮未清对象与未开宝箱将重置”，保存失败留在原地图。战斗中不提供回城。
- 返回标题前先完成一次稳定存档；保存失败则阻止离开并允许重试。

### 11.3 设置

- 画质：省电/标准/高画质。
- 战斗速度：×1/×2；只改变动画时间，不改变规则结算顺序。
- 音乐、音效 0～100。
- 减少闪烁与减少震动为两个独立开关，分别写 `reducedFlashes` / `reducedScreenShake`；前者移除强闪，后者移除屏幕位移。两者不能因一个为 true 就在存档中偷偷改写另一个。
- 显示调试 FPS 仅开发构建可见。

## 12. 视觉与像素规范

- 所有可见固定文案必须使用 `localization-spec.md` 的 key；结构化数值由 ViewModel 格式化，缺 key 时进入内容错误页，不能显示 raw key。
- 全部逻辑资源、物理规格、bundle、音频和帧名以 `asset-spec.md` 为准；本节只描述画面布局，不覆盖资源契约。
- 地图瓦片固定 16×16；探索角色/NPC 每帧固定 24×32，脚底锚点 `(12,28)`。
- 野外地图怪物使用 `EncounterDefinition.fieldSpriteId`，不能从敌方编队首位或 encounter kind 猜测；角色、NPC、遭遇三类探索 sheet 均使用同一脚底锚点。
- 普通角色和普通/精英敌人的战斗帧固定 48×48，锚点 `(24,42)`；Boss 固定 64×64，锚点 `(32,58)`。资源不得在同一类别混用尺寸。
- 探索角色固定四向 `idle` 4 帧（6fps）与 `walk` 6 帧（10fps），左右方向均提供独立帧；战斗单位固定 `idle` 4 帧、`attack` 6 帧、`skill` 8 帧、`hit` 3 帧、`down` 6 帧，帧率依次为 6/12/12/12/10。缺失 clip 是资源校验错误，不以第一帧代替。
- 纹理使用 nearest；默认关闭抗锯齿。
- 动态数字和频繁变化文本使用 BitmapText。
- 品质颜色同时配合边框形状/角标，不能只靠颜色区分。
- 深渊区域主色为紫黑/暗红，但正文文字对背景保持可读对比。
- 伤害数字最多同屏 20 个，超过时合并同一目标同一根行动的连续数字。
