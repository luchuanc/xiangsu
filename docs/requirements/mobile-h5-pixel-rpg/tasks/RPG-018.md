## 精确契约

Scene 每固定步只向 ExplorationState 提交 InputSnapshot，并用领域输出更新 View；actor `zIndex` 取脚底整数 Y。角色读取 CharacterDefinition.fieldSpriteId，NPC 读取 NpcDefinition.spriteId，地图怪读取 EncounterDefinition.fieldSpriteId，宝箱/portal 逐对象读取 frameId；缺资源阻断场景 prepare，不从 kind、action 或敌人队列猜图。交互半径 28 逻辑 px，按脚底/对象锚点距离平方后对象 ID 升序选唯一 NPC、未开宝箱或 portal，遭遇不进入此列表。宝箱调用 RPG-016 的通用 RewardService，以 chest namespace 生成后做 9999/120/80/30 dry-run，并把资产、claimed ID、opened object 在一个 revision 事务提交。EncounterContact 到达后立即冻结输入；SceneRouter 先 detached prepare 战斗资源，再由 EncounterTransitionService 用最新 GameStore 校验 expedition/map/object 未击败，调用 BattleFactory，并在同一个 revision 事务写玩家/安全位置、BattleSnapshot 及初始 enemyIdsBySlot 的 discoveredEnemyIds。只有提交成功才 attach 战斗 Scene；资源或保存失败保持原探索真源、解除冻结且不发现图鉴。
