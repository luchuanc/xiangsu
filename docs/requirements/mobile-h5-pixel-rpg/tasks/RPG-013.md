## 精确契约

BattleFactory 从已校验的 ExpeditionSnapshot + Map encounter object 创建战斗，逐项固化 expeditionId、encounterObjectId、encounterId、returnMapId 和 returnSafePosition，初始化 `battleRevision = 0`、`outcome = ongoing`，并逐单位固化可互相验算的 prePercentStats/staticPercentByStatBps/stats；角色 BattleUnit.currentHp 精确复制入战瞬间 CharacterProgress.currentHp，敌人满血。战斗进行中只修改 BattleSnapshot，CharacterProgress 保留入战值，直到胜利/撤退/战败终局事务按唯一规则写回，不能每段伤害双写长期状态。后续动态属性只能从前两项同区加算，不能从 stats 二次乘算。角色 cooldowns 只包含 basic、0～2 个非空主动和 ultimate。每轮开始只读取一次存活单位的 `effectiveSpeed`，排序键为 `[-speed, sidePriority, slot]`。该队列在本轮不可因速度变化重排；死亡立即跳过，召唤单位按 preferredSlots 填满到 maxAliveCopies 并标记 `eligibleRound = currentRound + 1`。合法普通行动必须经过 `DRAIN_PRE_ACTION` 再进入 RESOLVE_ACTION；受控制跳过必须进入 `action_skip_control` 合成根行动而不是直接跨过 TURN_END；死亡残留项才产生无根 defeated skip。Reducer 输入状态和领域事件，返回新状态；不得读取当前时间、全局随机数或 Pixi 节点。

| `metrics/reward/returnMapId/returnSafePosition` | 指标、奖励与回城 | 创建 metrics 全零且 18 个 Combo key 全存在；终局才允许 reward |

### 合法状态转换

`INIT → ROUND_START → TURN_START → (AWAIT_COMMAND | AI_DECIDE | RESOLVE_ACTION[control skip]) → AWAIT_COMMAND → VALIDATE → (AWAIT_COMMAND[invalid] | DRAIN_PRE_ACTION[valid]) → RESOLVE_ACTION → DRAIN_TRIGGERS → (TURN_END | VICTORY | DEFEAT) → (TURN_START[queue remains] | ROUND_END[queue empty]) → ROUND_START`。

终局只允许 `DRAIN_TRIGGERS → VICTORY/DEFEAT`，撤退为 `VALIDATE → RETREAT → COMPLETE`；`RETREAT/VICTORY/DEFEAT → COMPLETE`，任何其他跳转返回 `INVALID_BATTLE_PHASE`。死亡队列项只产生无根 `TURN_SKIPPED(defeated)`；控制跳过建立 `action_skip_control` 根行动并仍经过 `TURN_END`。
