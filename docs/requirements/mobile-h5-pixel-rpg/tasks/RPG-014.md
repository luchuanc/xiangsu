## 精确契约

所有行动从通过 `expectedBattleRevision`、行动者、阶段、技能可用性和 targetUnitIds 精确数量校验的 `BattleCommandV1` 开始。技能命令必须先生成一次 ResolvedSkill：USE_BASIC 先替换 basic，三类技能再按铭石 morph 等冻结顺序解析，最后用解析后的 target/front 校验 0/1 个命令目标；不得先按静态技能校验再偷偷改目标。敌方 fallback 槽即使引用 active SkillDefinition，也作为 basic 且不检查/写入模板 CD。每条合法指令从 `DomainContext` 取得唯一 rootActionId；`rootActionDefinitionId` 精确使用实际 SkillId/ItemId/`action_defend`/`action_retreat`。一次根行动内伤害、治疗和资源变化按 `game-design.md` 5.4 的成本→beforeAction/DRAIN_PRE_ACTION hook→根 effects→行动能量→afterRootAction→DRAIN_TRIGGERS→终局顺序返回 `BattleResolutionV1`，事件只能使用 `BattleDomainEventV1` 判别联合且 sequence 连续；本任务先实现空 hook，RPG-015 接入真实触发且不得改变阶段顺序。DEFEND 固定展开 status_guard_30 的单一 effect；RETREAT 使用三事件序列且不进入触发队列。直接伤害防御常数只能是 300；`USE_ITEM` 同时读取权威 InventoryState，只接受 battle context 消耗品并按物品 target/effects 解析，成功 resolution 恰好声明 consumedItem ×1。SaveCoordinator 只在同一事务保存该扣除与 BattleSnapshot，失败整体不修改、不返回给动画层；其他命令 consumedItem=null。冷却 N 表示未来 N 个本人回合不可用；Boss 遭遇的 retreat 命令必须返回禁用原因且不消费回合。
