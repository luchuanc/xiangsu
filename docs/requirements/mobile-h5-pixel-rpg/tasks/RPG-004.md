## 精确契约

`save(expectedRevision,nextSave)` 在单一 readwrite transaction 中先读取数据库实际 revision 再 CAS；不一致返回 `STALE_REVISION`，多标签页旧快照只能要求重载。成功后 revision 加 1、updatedAt 更新；失败不改权威 GameStore。战斗 candidate 失败时丢弃 events 并复用原 command/candidate 或从旧快照确定性重算；探索位置只允许一个可合并 pending snapshot；资产/交易/模式开始 pending 时阻断新写命令。未知 schema/contentVersion 不读取业务字段、不覆盖原记录。新游戏覆盖需调用独立 `replaceAfterConfirmation`，repository 本身不承担 UI 确认。新游戏默认值必须显式包含 `skillStoneFocusCharacterId`、battleAssist 六角色 null 记录、空 `bossRetryUnlockedFloorIds/clearedEchoIds`、`echoCharges=0/echoAttemptSequence=0`、堆叠总量规则和所有实例 `reforgeCount=0`；远征快照显式包含 mode/abyssEchoId/focusedEliteStoneConsumed，并按 mode 校验 floor/map、位置、对象列表与保护范围。bossRetry/abyssEcho 的开始、终局及重试必须保持商店三字段逐字节不变；回响 pending/failed 的 reward 必须为空。
